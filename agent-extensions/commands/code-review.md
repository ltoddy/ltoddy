---
name: code-review
description: 审查当前 Git 暂存区（staged）中的代码变更
---

为 git 暂存区（staging area）中已暂存的变更提供代码审查。

为此，请严格按以下步骤执行：

1. 检查暂存区中是否有已暂存的变更（例如使用 git diff --cached --stat）。如果没有暂存变更，则不要继续。
2. 获取代码库中相关 AGENTS.md 文件的路径列表（不包括内容）：根目录的 AGENTS.md 文件（如果存在），以及暂存区中修改过的文件所在目录中的任何
   AGENTS.md 文件。
3. 查看暂存区变更（例如 git diff --cached），并返回变更摘要。
4. 然后，并行启动 5 个 agent 独立对变更进行代码审查。这些 agent 应执行以下操作，然后返回问题列表及每个问题被标记的原因（例如
   AGENTS.md 符合性、bug、历史 git 上下文等）：
   a. Agent #1：审计变更，确保它们遵守 AGENTS.md。注意，AGENTS.md 是 agent 编写代码时的指导，因此并非所有指令在代码审查期间都适用。
   b. Agent #2：阅读暂存区中的文件变更，然后对明显的 bug 进行浅层扫描。避免阅读变更之外的额外上下文，只关注变更本身。聚焦于大的
   bug，避免小问题和吹毛求疵。忽略可能的误报。
   c. Agent #3：阅读被修改代码的 git blame 和历史记录，结合该历史上下文识别任何 bug。
   d. Agent #4：阅读曾改动过这些文件的先前提交（git log）和审查记录，检查是否有同样适用于当前暂存区变更的问题。
   e. Agent #5：阅读被修改文件中的代码注释，确保暂存区中的变更遵守注释中的任何指导。
5. 对于第 4 步中发现的每个问题，并行启动一个 agent，向其提供暂存区变更、问题描述和第 2 步得到的 AGENTS.md 文件列表，并返回一个分数以表示该
   agent 对每个问题是真实还是误报的置信程度。为此，agent 应在 0-100 的范围内对每个问题打分，表示其置信程度。对于因 AGENTS.md
   指令而被标记的问题，agent 应再次核实 AGENTS.md 是否确实具体指出了该问题。评分标准如下（逐字将以下评分标准提供给 agent）：
   a. 0：完全不确信。这是经不起简单推敲的误报，或是先前已存在的问题。
   b. 25：略有信心。这可能是真实问题，但也可能是误报。agent 无法确认它是真实问题。如果是风格问题，则它未被相关 AGENTS.md 明确指出。
   c. 50：中等信心。agent 能够确认这是一个真实问题，但它可能只是吹毛求疵或在实践中不常发生。相对于变更的其他部分，它并不十分重要。
   d. 75：高度确信。agent 再次核对了该问题，并确认它极有可能是一个在实践中会遇到的真实问题。暂存区变更中现有的做法不足。该问题非常重要，会直接影响代码的功能，或者它是相关
   AGENTS.md 中直接提到的问题。
   e. 100：绝对确定。agent 再次核对了该问题，并确认它绝对是一个真实问题，在实践中会频繁发生。证据直接证实了这一点。
6. 过滤掉任何得分低于 80 的问题。如果没有符合此标准的问题，则不要继续。
7. 重复第 1 步中的检查，以确保暂存区中仍然存在已暂存的变更。
8. 最后，在终端中输出审查结果。撰写结果时，请记住：
   a. 保持输出简洁
   b. 避免使用表情符号
   c. 引用相关的代码和文件

误报示例（适用于第 4 和第 5 步）：

- 先前已存在的问题
- 看起来像 bug 但实际上不是 bug 的内容
- 资深工程师不会指出的吹毛求疵
- linter、类型检查器或编译器会捕获的问题（例如缺失或错误的导入、类型错误、失败的测试、格式问题、诸如换行之类的苛求的风格问题）。无需亲自运行这些构建步骤——可以放心地假设它们会作为
  CI 的一部分另行运行。
- 一般的代码质量问题（例如缺少测试覆盖、一般性安全问题、文档不佳），除非 AGENTS.md 中明确要求
- 在 AGENTS.md 中被指出、但在代码中被明确压制的问题（例如由于 lint 忽略注释）
- 很可能是有意为之的功能变更，或与更广泛变更直接相关的变更
- 真实问题，但出现在用户未修改的行上

注意事项：

- 不要检查构建信号，也不要尝试构建或对应用进行类型检查。这些会另行运行，与你的代码审查无关。
- 使用 `git` 命令获取暂存区变更和历史记录（例如 `git diff --cached`、`git blame`、`git log`），而不是使用网络工具
- 先制作一个待办事项列表
- 你必须引用并链接每个 bug（例如，如果引用 AGENTS.md，则必须链接它）
- 对于最终输出，请严格按照以下格式（假设在此示例中你发现了 3 个问题）：

---

### 代码审查

发现 3 个问题：

1. <问题简述> (AGENTS.md says "<...>")

<引用文件和行范围，格式为 相对路径:起始行-结束行，例如 src/utils/validate.ts:10-15>

2. <问题简述> (some/other/AGENTS.md says "<...>")

<引用文件和行范围，格式为 相对路径:起始行-结束行>

3. <问题简述> (bug due to <file and code snippet>)

<引用文件和行范围，格式为 相对路径:起始行-结束行>

---

- 或者，如果没有发现问题：

---

### 代码审查

未发现问题。已检查 bug 和 AGENTS.md 符合性。

- 引用代码时，请严格遵循以下格式：`相对路径:起始行-结束行`（例如 `src/utils/validate.ts:10-15`）
    - 路径为相对于仓库根目录的路径
    - 在你引用的行前后各至少提供 1 行上下文，并以其为中心（例如，如果你引用的是第 5-6 行，你应该引用 `4-7` 行）
